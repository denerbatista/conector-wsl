WSL + Windows Workspace Connector

Conector MCP local que dá ao Claude acesso controlado à sua máquina: terminal do WSL, PowerShell do Windows, sessões persistentes e arquivos dentro das pastas que você libera.

Instalar Ferramentas Configurar Segurança Privacidade Suporte

O que ele faz

  • Executa comandos no WSL (bash) e no Windows (PowerShell), avulsos ou em sessões que guardam a pasta atual.
  • Lê, escreve e lista arquivos, sempre dentro das pastas liberadas.
  • Abre arquivos, pastas e URLs no Windows com o app padrão.
  • Detecta sozinho a distro WSL, o usuário Linux e o usuário Windows. Por padrão libera /home/<usuário-linux> e /mnt/c/Users/<usuário-windows>.
  • No Claude Code, que já tem terminal próprio, entra em modo silencioso e não gasta contexto.

Instalar

Requisitos

  • Windows 10 ou 11 com WSL 2 (ou Linux/WSL, sem as ferramentas de Windows).
  • Node.js 20 ou mais novo.

Como plugin do Claude (Cowork e Claude Code)

Instale o plugin conector-wsl pelo diretório de plugins do Claude. O plugin sobe o servidor com node ${CLAUDE_PLUGIN_ROOT}/src/index.js, e o Claude instala as dependências (@modelcontextprotocol/sdk e zod) a partir do package-lock.json.

Pelo npm

npm install -g claude-wsl-terminal-connector

O instalador adiciona o conector ao Claude Desktop. Depois, reinicie o Claude Desktop.

Pelo arquivo .mcpb

Baixe o .mcpb do release mais recente e abra no Claude Desktop em Settings › Extensions › Install from file.

Exemplos de uso

  • “Rode npm test no projeto ~/myprojects/app e me diga o que falhou.”
  • “Liste os arquivos da minha Área de Trabalho no Windows.”
  • “Abra uma sessão no WSL, entre em ~/site e faça o build.”
  • “Abra o relatório C:\Users\eu\Documents\relatorio.pdf.”

Configurar (opcional)

Tudo é detectado sozinho. Se quiser mudar, use estes campos (ou as variáveis de ambiente):

CampoVariávelPadrão
Diretório inicialWSL_CONNECTOR_DEFAULT_CWD/home/<usuário>
Pastas liberadasWSL_CONNECTOR_ALLOWED_ROOTShome do WSL e pasta do usuário no Windows
Distro WSLWSL_CONNECTOR_DISTROa distro padrão
Tempo limiteWSL_CONNECTOR_TIMEOUT_MS120000 ms
ModoWSL_CONNECTOR_MODEauto (full no Windows, silent no Claude Code em Linux)

Segurança e o que ele executa

  • Toda operação de arquivo e de terminal é validada contra as pastas liberadas. Caminhos fora delas são recusados.
  • Os comandos rodam com o seu usuário, com as mesmas permissões que você tem no terminal.
  • Processos iniciados: wsl.exe --exec bash -lc (ou /bin/bash -lc no Linux) e powershell.exe.
  • Nenhuma requisição de rede. A única exceção é opcional: com WSL_CONNECTOR_PREWARM definido, ele roda npx -y <pacote@versão> --help para aquecer o cache do npm. O plugin não define essa variável.
  • Sem telemetria. Veja a política de privacidade.

Limites conhecidos

  • Não há TTY interativo real (programas que pedem entrada no meio da execução não funcionam).
  • Sessões WSL guardam a pasta e as variáveis exportadas; aliases e funções não persistem.
  • Sessões PowerShell guardam só a pasta atual.
  • Arquivos são tratados como texto UTF-8.
